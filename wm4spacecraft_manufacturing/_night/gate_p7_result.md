# P7 분포 게이트 결과 (2026-08-13 01:08:05, 배경 부하 K=15 + 측정 1 = 16)

설계: 단독 8판 순차 → 배경 부하(본 스윕 샤드 63개, K=15) 아래 측정 8판 순차.
측정 대상은 `zone` seed 1 `noop` — LLM 이 끼지 않아 API 지연이 부하 효과와 섞이지 않는다.
계획서의 `--seeds 1,2`(14샤드)는 약 7분이면 말라 측정(약 22분) 후반이 부하 하가 아니게 되므로,
9시드 63샤드로 늘려 측정 전 구간에서 부하를 유지했다. 실측 julia 프로세스 수는 측정 8회 내내 15로 일정.

```
== P7 분포 게이트 (alpha=0.05) ==
  단독 표본 8, 부하 하 표본 8
  PASS  sim_seconds: 양쪽 모두 상수 123.9 -- 검정 생략
  PASS  closed: 양쪽 모두 상수 263 -- 검정 생략
  PASS  complete: Fisher exact p=1.0000  (단독 0/8 완주 / 부하 0/8 완주)

부하가 분포를 옮겼다는 증거 없음. 병렬 진행 가능.
주의: 8+8 표본은 큰 효과만 잡는다. 이것은 안전의 증명이 아니다.
```

## 예상 밖의 소득: 이 설정은 재현된다

16판(단독 8 + 부하 하 8)이 `sim_seconds`·`closed` 에서 **전부 동일했다**
(123.9 / 263). 게이트는 '분포가 옮겨졌다는 증거 없음'만 주장하도록 설계됐지만,
실제로 나온 것은 그보다 강한 결과다 — K=16 부하가 이 판을 **전혀** 건드리지 않았다.

이는 저장소가 기록해 온 비결정성(2026-08-11 실측: monitor frames 214→204, n_closed 149→123)이
**모든 설정에 걸린 성질이 아님**을 뜻한다. 적어도 `zone`/seed 1/`noop` 은 결정적이다.
따라서 비결정성의 원인은 시뮬레이터 코어가 아니라 다른 곳(정책 레인·라우터·LLM 응답 등)에
있을 가능성이 높다. 이 16판은 그 규명의 첫 체계적 원자료다.
