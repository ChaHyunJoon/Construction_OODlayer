Hyper-parameter sweep — is 300/0.08 optimal?

The collaborator flagged the surrogate's max_iter=300 / lr=0.08 (HistGBR) as hand-set. Answer: tree count barely matters (100≈300≈600); the levers are learning-rate and the depth cap. The hand-set config is beaten on both discriminative datasets — and on the larger one, significantly.

"More than one right solution?" — tie-aware regret & cost sensitivity

When the top-2 macros are within 5% of the reachable span, the arg-max is arbitrary and low regret is trivial, not skill. Splitting regret into tie vs non-tie instances is the honest view — and the surrogate does better on clear-cut decisions (reg 0.120, top-1 0.86) than on ties.

04

What signal does the surrogate use?

Permutation importance on the held-out value target. The surrogate reads within-kind continuous physical state — SoC, agents-pending, severity — not the OOD kind label. Zeroing the kind one-hot moves regret by −0.001; zeroing SoC hurts most. This is the direct evidence for "learnable beyond the kind."

Permutation importance — held-out closed-count MAE increase

graded_all · tuned HGB · higher = more relied upon

Read. soc, agent_pending, severity dominate; the four kind_* one-hots sit near the bottom (~1). A per-kind lookup could not produce this — the model is reading the battery level and the queue depth, exactly as the ladder's within-kind flips imply. The small negative ablation deltas for zone_overlap/progress hint at mild overfitting at n=31 → more data would help.

05

DSPy producer trial — programming vs prompting

The dspy library needs numpy≥1.26, which conflicts with the project's TensorFlow (numpy<1.24), so DSPy's three core ideas were implemented on the OpenAI SDK directly to keep the env intact. Result: demonstrations (the "programming" step) rescue a weak zero-shot prompt, but no LLM configuration beats the forest surrogate.

LOO decision-regret by producer — graded_hs_all (n=20)

Three honest findings. (1) Few-shot demos are the real DSPy lever — they cut mini's regret 0.544→0.190. (2) BootstrapFewShot hurt both models: filtering to self-consistent demos drops coverage and keeps only the easy cases, and a weak base model's "self-consistent" set is only ~50% reliable. (3) The cheap forest wins on quality and is ~10⁶× cheaper per decision — so keep the surrogate primary and reserve an LLM for genuinely novel OOD the surrogate has never seen.
06

What's blocked & environment notes

Julia label regeneration — blocked at source. Every oracle generator includes decpomdp/examples/ood_env.jl, which is absent from this checkout (only src, test, tools, docs, scripts, LDraw_files, results exist). The graded dumps were produced in a different environment. Extending zoneblk or boosting n is impossible until decpomdp/examples/ is restored. Julia 1.10.11 itself works — a smoke run precompiled fine and only failed on the missing include.
DSPy library incompatible with this env. dspy 3.x requires numpy≥1.26; the project's tensorflow-intel 2.12 requires numpy<1.24 — mutually exclusive. A stray --only-binary retry briefly upgraded numpy to 2.2.6; it was restored to 1.23.5 and the sklearn/pandas stack re-verified, so the env is back to its original state. The DSPy trial ran on the OpenAI SDK instead (51 calls/model, gpt-4o-mini & gpt-4o).
Small-n is the binding constraint. The tuning win is significant at n=31 but not n=20; several ablation deltas are slightly negative (overfitting). The single highest-leverage next step is more labelled instances — which is exactly what the blocked generator would supply.

Recommended next actions

  1. Re-tune the surrogate on decision-regret; drop the depth=4 cap.
    Adopt HGB depth=None, lr≈0.2 (or ExtraTrees-200 for best top-1). Significant win on n=31; keep the sweep objective as regret + tie-rate, never R².
  2. Reconcile the deployed producer with the evaluated one.
    The demo's RF 60/d6 loses to the eval HistGBR on graded data (0.193 vs 0.150) — the decision-equivalence claim holds on the easy set but breaks on graded. Re-export the deploy forest with the tuned HP.
  3. Restore decpomdp/examples/ to unblock label generation.
    Then regenerate the missing zoneblk1.2 severity + more seeds. This is the single highest-leverage move — it converts the "not significant at n=20" results into decisive ones and repairs the zone ladder.
  4. Report reg_NOTIE as the headline; track the tie fraction.
    29% of raw instances tie. Publish decision-consequential regret separately, and design new severities to straddle the boundary so the tie fraction shrinks.
  5. Keep the surrogate primary; scope the LLM to novel OOD.
    No LLM config beat the forest, at ~10⁶× the cost. Use an LLM producer only where the surrogate is out of distribution — and prefer few-shot demos over bootstrap filtering.
