Three cost claims, each measured

Faster

Millions × faster, both ends measured

Each true-planner verification is a measured 64 s ConstructionBots sim. A guaranteed-feasible LLM policy must run several — 193 s per decision. The surrogate answers in 0.10 ms: 1,935,336× faster at the same decision quality.

More accurate

Beats an LLM that skips verification

The LLM-only planner reads the OOD kind and applies the textbook macro — regret 0.552, only 75% of builds finish. The surrogate reads state within the kind: regret 0.100, 100% complete. Advantage +0.452, CI-significant.

Cheaper per build

And it amortizes fast

Over one build's OOD stream, LLM→solver spends 13 min just deciding; the surrogate spends 0.4 ms. Its one-time data-gen cost is repaid after ~102 decisions (~26 builds).

Evidence

The ground truth completes 100% — how, without cheating

The brute-force TAMP oracle is the reference ceiling, so it must be able to finish every build — otherwise "regret vs the oracle" is measured against a broken reference. On the first benchmark it completed only 80%; the other 20% split into two causes, each fixed on its own terms (no logical or physical shortcut):

  • No-spare fault (was physically impossible). Two instances faulted a robot with zero spares configured — there is literally nothing to replace it with, so no macro can finish. Fixed by provisioning one spare (the realistic operating regime): Replace now completes (283/297) and is strictly required — every other macro still fails. A 0-spare fault is genuinely unrecoverable and is excluded as out-of-scope for a decision benchmark.
  • Zone endgame wedge (was a stale label). Two zone instances were carried over from an older pre-recovery world; regenerated with the same reactive endgame recovery the real system runs (reform-interval 120 + stuck-carrier force-close), the zone build completes on every macro — the no-go region is evaded by restaging, not by routing through it.

Result: oracle completion 20/20 = 100%, and the surrogate matches it (100%) while the un-verified LLM planner still finishes only 75%. Crucially, the necessity signal survives the fix: the surrogate still beats the best state-blind rule by +0.452 regret [+0.250, +0.652], because the within-kind flips (battery SoC ladder, fault vs idle-fault) are untouched.

Why this is a fair fight

  • Measured, not assumed. Tsim (64 s median) is read from the oracle's own label_seconds; Tsurr (0.10 ms) is timed on the deployed forest; Tllm (1.0 s) is 6 live gpt-4o-mini calls. Only the LLM's accuracy is modeled — at its best case.
  • The LLM gets every benefit. Best-case accuracy (always reads the kind right) and the cheapest, fastest model. A frontier planner on full state is slower and pricier — this under-states the surrogate's edge. A live probe still caught it: asked about a healthy battery at SoC 0.52, the LLM chose Replace (wastes a spare) where the oracle chooses NOOP.
  • Honest physics. Tsim is measured with the reactive motion stack (RVO) on — the regime where the best macro is congestion-dependent. The saving comes from amortizing process-parallel physics, not from cheaper physics.
  • The decision-relevant benchmark. Scored on the cost-aware graded task, where a Replace-everything heuristic can't tie the oracle — so the comparison isn't an artifact of an easy task.

With a ground truth that completes 100%, the comparison is clean: the surrogate matches the oracle ceiling on completion at near-oracle regret in 0.10 ms — while an LLM planner is either fast-but-wrong (75% complete) or right-but-minutes-slow. The surrogate is the only policy that is simultaneously cheap, accurate, and completion-safe.
