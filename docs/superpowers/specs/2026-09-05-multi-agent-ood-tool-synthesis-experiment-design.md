## 1. 목표

**multi-agent LLM 워크플로가 OOD(분포 밖) 사건을 다루는 데모를 만든다.**

정확히 말하면, 학습된 정책이 **행동 어휘를 갖고 있지 않은** 사건이 들어왔을 때
LLM 에이전트 여럿이 협의해 **런타임에 새 도구(Julia 함수)를 합성**하고, 그 도구가
살아 있는 시뮬레이터에 등록·집행되어 **세계를 실제로 바꾸는** 것을 보이는 것이다.

### 1.1 이 데모가 주장하려는 명제

> 학습 분포 밖의 사건에서, 고정된 행동 어휘로는 표현할 수 없는 개입을
> multi-agent 추론이 **새 도구로 합성**해 집행할 수 있다.

### 1.2 명제의 세 부분과 각각의 증거

| 부분 | 무엇을 보여야 하나 | 증거 채널 |
|---|---|---|
| **분포 밖이다** | 사건이 surrogate 의 `train_kinds` 밖이고 라우터가 LLM 으로 escalate 한다 | `routing_kind` · `[router] … → escalate to LLM` |
| **어휘로 표현 불가다** | agent-2 가 `expressible=False` 를 낸다 | 🔴 **합성의 유일한 방아쇠** |
| **집행돼서 효과가 있다** | 도구가 등록·호출되고 **세계가 바뀌고** 결과 지표가 움직인다 | 사다리 L0~L4 + 결과 지표 |

🔴 **셋째 부분이 이 레포가 반복해서 실패해 온 자리다.** 첫째·둘째는 여러 번 초록이었다.

## 2. 판정 정본 — 사다리

기계 판독 전용: `tools/monitor/ladder_report.py`. 🔴 **손으로 로그를 읽어 채점하지 않는다.**

| 칸 | 술어 | 뜻 |
|---|---|---|
| **L0** | `wrote == true` | 모델이 코드를 썼다 |
| **L1** | `registered == true` | 규약 검사를 통과해 살아 있는 모듈에 심겼다 |
| **L2a** | `args_from == :calls` | 인자가 채널로 전달됐다 |
| **L2b** | `steps[1].status === :success` | 예외 없이 끝났다 |
| **L3** | `interface_calls ≠ []` | 광고된 세계 함수를 실제로 불렀다 |
| **L4** | `world_delta_body` 다섯 축 중 하나라도 ≠ 0 | **세계가 바뀌었다** |

🔴 **L2b 의 술어를 `!== nothing` 으로 되돌리지 말 것.** 옛 술어는 `:threw` 로도 충족돼
**명제가 거짓인데 초록으로 읽혔다.**

🔴 **삼상 규약이 이 레인의 헌법이다**: `nothing` = 못 쟀다 · `false` = 쟀는데 거짓 ·
`[]`/`0` = 쟀는데 비었다/안 움직였다. **이 셋을 뭉개는 코드는 결함이다.**

### 2.1 사다리가 **못 재는 것** — 알려진 구멍

- 🔴 **"옳게 했는가" 를 재는 칸이 없다.** L4 는 "세계가 바뀌었나" 만 묻는다. 지친 로봇을
  *고장난* 로봇으로 취급하는 도구도 binding 을 바꾸므로 L4 가 초록이 된다.
- 🔴 **헤드라인 지표가 `PROJECT INCOMPLETE` 에서 빨개지지 못한다** [측정, §4.1].
  ⟹ **완주는 가드레일이 아니라 차단 게이트여야 한다**: 미완주 판의 에너지 수치는
  비교 대상이 아니다(유휴 방전이 지배한다).
- `world_delta_body` 의 다섯 축(`closed`·`active`·`n_edges`·`n_binding_changed`·`n_weights_changed`)은
  **배터리 스왑 · zone · spare pool · 배송 기록을 한 축도 안 덮는다** [측정].
  그 표면에서 일하는 도구는 L4 가 **거짓 0** 이 된다.

## 3. 결과 지표

### 3.1 헤드라인 — 최종 `min_soc`

**정식화**: mild battery 로는 build 가 안 깨지므로, *"가장 낮은 battery SoC 가 얼마나 높게
유지되는가"* 로 평가한다. 그것이 **낮은 SoC 로봇을 가벼운 payload 에 배정한 결과**다.

🔴 **`min_soc` 은 `energy_J[대상]` 의 충실한 단조 변환이다** [측정]:
사건 후 18개 구간 전부에서 `Δsoc/ΔE = 1.208e-7` (오차 ~1%).

| 구간 | ΔenergyJ | Δsoc | 비 |
|---|---|---|---|
| t 351→401 | +381.2 | −4.6e-5 | 1.21e-7 |
| t 701→751 | +311.4 | −3.7e-5 | 1.19e-7 |
| 사건 후 전체 | +6396.7 | −7.73e-4 | **1.208e-7** |

⟹ `energy_J` 쪽이 해상도가 4자릿수 높고 `min_soc` 쪽이 해석이 쉽다. **둘 다 보고한다.**

### 3.2 척도 무관 헤드라인

```
N = 1 − ΔE_처치 / ΔE_대조        (ΔE = 사건 프레임 이후의 energy_J[대상] 증분)
```
🔴 **런 전체 누적을 쓰지 않는다** — 사건 **전** 구간은 정의상 두 런이 같으므로 N 이 희석된다.
`N > 0` 이 성공 방향.

### 3.3 효과 크기 — 결과를 보기 전에 못박는다

대조 실측: 주입 직후 `soc = 0.149803`(t=151), 최종 `min_soc = 0.14903`(t=1024)
⟹ **사건 후 대상이 실제로 쓴 것은 `0.000773 soc` 뿐이다.**

| 대상의 사건 후 부담을 | 최종 `min_soc` |
|---|---|
| 0% 줄임 (= 대조) | 0.149030 |
| 30% 줄임 | ≈ 0.149262 |
| 100% 줄임 (유휴 상한) | ≈ 0.149803 |

숫자가 **소수 넷째 자리**에서 움직인다. 잡음 바닥이 0 이라 신호이지만,
**발표는 절대값이 아니라 N 으로 한다.**

### 3.4 보조·가드레일
- 보조: `soc_spread`(wear-leveling) · 함대 `total_energy_J`
- **가드레일**: `t` / `n_closed`. 🔴 헤드라인 금지. §2.1 대로 **완주는 차단 게이트**다.

### 3.5 기각한 지표
- **SwapBattery / 배송 수**: mild 의 팔 집합은 `battery_arms` 가 **NOOP 하나**로 못박는다
  (게이트 `test/battery_ladder_is_deep_only.jl`). 구조적 불가능 [측정].
- **makespan**: 정수 걸음이라 거칠고 완주 사건으로 끝난다.
- **`usage_s`**: `enable_hazard!` 를 요구하는데 데모 레인은 안 부른다. 켜면 `DRAIN_FACTOR_HOOK` 이
  설치돼 **모든 SoC 수가 바뀐다** ⟹ 공짜 계측이 아니다.
- 🔴 **`battery_payload_proxy_{max,total}`**: `_battery_load_features`(`tools/monitor/policy.jl`)가
  payload 를 팀 크기로 **안 나누고** 넣는다 — 120쌍 중 9쌍(**7.5%**) 순위 역전.
  옳은 것은 `cargo_burden_after`(`src/navigator/payload_bias.jl`), 살아 있는 단언은
  `test/forbid_heavy_cargo.jl` 의 testset `"cargo_burden_after 의 삼상 규약과 나눗셈"`.
  🔴 **이 틀린 값이 지금도 프롬프트로 모델에게 간다** — 미수정, 알려진 결함.

### 4.2 사건 설정

```
DEMO_MODEL=tractor.mpd DEMO_OOD=battery DEMO_BSOC=0.85 DEMO_CASE_TAG=battery_mild
DEMO_BATTERY_STEPS=40,120 DEMO_POLICY=dspy DEMO_ANIM=0
```

🔴 **`DEMO_BSOC=0.85` 는 실측으로 교정된 값이다.** 이전 판의 `0.45` 는 **사건을 일으키지
않았다** [측정]: `tractor__none.jsonl`(사건 없음)과 `tractor__battery_mild.jsonl`(주입)이
**18프레임 전부 동일** — 로봇 위치 **324/324 일치, 차이 0건**.
원인은 `set_battery_derate!(hi = 0.5, min_factor = 0.35)` 다. `DEMO_BSOC` 는 **뺄셈**이라
0.999855 → **0.549786**, 즉 derate 문턱 **바로 위**라 속도 계수가 **정확히 1.0** 이었다.
그동안 프롬프트의 mild 자연어는 모델에게 "정상보다 느리게 움직인다" 고 말해 왔다.

| `DEMO_BSOC` | soc_after | 속도 계수 | 라우팅 |
|---|---|---|---|
| 0.45 (옛) | 0.550 | **1.000 — 무효과** | mild |
| **0.85** | **0.150** | **0.494 (반속)** | **mild** ✅ |
| 0.90 | 0.100 | — | 🔴 deep → surrogate |

🔴 **런 무효 조건**: `routing_kind` 가 `"unknown:battery_mild"` 가 아니면 그 런은 무효다.
`"battery"` 면 surrogate 로 샌 것이고 아무것도 안 잰 것이다. **채점하지 않는다.**

- `DEMO_BATTERY_STEPS=40,120` 은 **필수**다. 기본 창은 낮은 SoC 로봇을 뽑아
  `routing_kind="battery"` 로 새서 $0 쓰고 아무것도 안 잰다.
- 🔴 `REQUIRE_SYNTH_MULTI_AGENT` 는 **켜지 않는다** — 어떤 레인도 안 읽어서 옳은 런이
  `FAIL flag_off` 로 죽는다.

## 5. 어휘 설계 — 무엇을 보여주고 무엇을 감추는가

🔴 **광고 규칙은 `names(CB)`(exported only)다** [측정]. 별도 allowlist 가 없다 ⟹
**`export` 한 줄 = 광고 한 개.** 감춤 게이트는 `test/world_interface_current.jl` 의
testset `"(4) 🔴 비공개 impl 은 실리지 않는다 (설계 D6)"`.

⚠️ **감춤은 수동적이지 않다**: `check_impl_conventions` 규약 5 에 `impl_name_exists_withheld`
전용 거절 사유가 있어, 모델이 감춘 이름을 맞혀 부르면 **등록이 거절된다**.

### 5.1 설계 원칙 — 능력은 주고 답은 주지 않는다

**주조 도구가 할 수 있는 일의 집합 = 광고된 어휘의 합성 폐포.** 배정에 쓰는 동사가 어휘에
하나도 없으면 그 어휘의 **어떤 합성도** 배정에 못 쓴다 ⟹ L4=0 은 모델의 추론 실패가 아니라
**어휘 설계의 귀결**이고, 프롬프트에 규칙을 더해서는 절대 안 열린다.

⟹ **재배정 능력은 광고한다.** 그러나 *어느 로봇의 어느 작업을 누구에게 넘길지*,
*payload×SoC 교환비가 무엇인지* 는 어휘 어디에도 없다 — **그 전부가 모델의 추론 부담이다.**

### 5.2 현재 상태

| 동사 | 상태 | 비고 |
|---|---|---|
| `release_pending_assignments!` | ✅ 광고 (`b3a62982`) | 🔴 `export` 만으로는 **무동작**이었다 — 위치인자 `invariant::InvariantSpec` 이 타입 폐포 밖이라 `callable=false` 였고 `_CURATED_SEEDS` 가 필요했다 |
| `forbid_heavy_cargo!` | ✅ 광고 (`5a2ede9d`) | 위치인자가 `env` 하나라 폐포 문제 없음 |
| `ood_event_target()` | ✅ 광고 (`09204a2c`) | 사건 대상 id 를 **객체로** 반환. §6 |
| `recover_stalled_teams!` · `resolve_schedule_wedge!` · `force_advance_stuck_carrier!` | 🔒 감춤 | **발명 능력 축**을 계속 잰다 |

⟹ **조합 능력 축(광고된 것들을 새 규칙으로 엮는가)과 발명 능력 축(없는 것을 지어내는가)이 분리됐다.**

### 5.3 알려진 프롬프트 결함 (미수정)

AFTER EVERY TOOL BODY"* 라고 적는데 **거짓이다**. 실제 하네스(`_resolve_if_needed!`)는
`surface ∈ RESOLVE_SURFACES = {"sched","milp"}` 일 때만 재풀이한다.

## 6. 접지 — 다섯 런을 죽인 실패 부류

**식별자 환각이 다섯 런 연속으로 한 겹씩 안쪽으로 옮겨갔다** [측정]:

| 런 | 환각의 층 | 고친 것 | 다음 판 |
|---|---|---|---|
| 1 | 필드 이름 `node.assigned_robot` | 타입 폐포 확장 | 환각 0 — 대신 L3=[] |
| 2 | 키 타입 `soc["R1"]` | 호출 선호 + 반환 예시 | L3 최초 초록 — 대신 키 타입에서 죽음 |
| 3 | 규약 위반(kwarg 기본값) | 식별자 규칙 6 | `"R1"` 소멸 — 대신 L1 붕괴 |
| 4 | 맨 정수 `::Int64` | 재배정 동사 광고 | L1·L2a·L3 초록 — 대신 인자 타입에서 죽음 |
| 5 | **인자 채널**이 `"R1"`·`"R2"` 를 실어 body 의 옳은 폴백을 무력화 | 사건 대상 채널 | body 는 옳았다 — 인자가 덮어썼다 |

🔴 **"규칙 하나 더" 를 처방으로 삼지 말 것.** 규칙을 더할 때마다 실패가 **사라지지 않고 옮겨갔다.**
공통 원인은 하나였다 — **모델이 사건 대상을 지목할 채널이 없어 매번 지어냈다.**

### 6.1 처방 — 규칙이 아니라 기전
1. **`ood_event_target()`** (`09204a2c`): 반환 타입이
   `Union{Nothing, BotID{DeliveryBot}}` 로 좁다. 🔴 `nothing` = **기록 안 됨**이고 유효한 로봇이 아니다.
2. **인자 채널 기계적 거름** (`bc1e9d5b`): **주조 원시에 한해**, 이 세계의 NL 렌더러가 만드는
   로봇 이름 모양(`^(?:robot[ _-]*)?R\d+$` 등)인 kwarg 값을 바인딩하지 않고 선언된 기본값으로
   되돌린다. 여집합이 아니라 **양성 매칭**이다(`"zone_blk_1"` 같은 정상 문자열을 죽이지 않으려고).
   🔴 **`_is_generated` 로 게이트한다** — 손으로 쓴 원시에 적용하면 `faulted`/`agent` 가 둘 다
   `nothing` 이 되어 **release 범위가 전 함대로 넓어진다**(변이시험 m5 가 이것을 잡았다).
   `dropped_args` 가 삼상으로 기록 줄에 실린다.
3. **짧은 형식 수용** (`c444666d`): 모듈 비수식 `"BotID{DeliveryBot}(4)"` 도 받는다.
   정준형은 `string(rid)` = `"ConstructionBots.BotID{ConstructionBots.DeliveryBot}(4)"` [측정].

## 7. 🔴 오라클 계열 — LLM 을 빼고 전제를 먼저 검증한다

유료 런 다섯이 전부 body 가 세계에 닿기 **전에** 죽어서, 이 레포는 **"body 가 끝까지 돌면 무슨
일이 일어나는가" 를 한 번도 관측한 적이 없었다.** 실험 전체가 *"낮은 SoC 로봇의 일을 덜어 주면
`min_soc` 이 올라간다"* 는 전제 위에 서 있는데 아무도 그것을 재지 않았다.

⟹ **LLM 을 빼고 손으로 쓴 이상적 body 로 먼저 답한다.** 장치는 `DEMO_SYNTH_FIXTURE`
(`synth_fixture_lane`, `tools/monitor/policy.jl`, 커밋 `b99c2ce3`).

🔴 **우회 장치의 설계 요건 셋** — 이 레포 최악의 실패 모드를 막는다:
1. **기본 꺼짐**. 빈 환경변수면 객체를 그대로 반환한다(검증됨: 출력 0).
2. **조용할 수 없다**. 결정마다 `🔴🔴🔴 ORACLE BYPASS ACTIVE` 배너(경로 · `sha256[1:16]` ·
   `impl_name` · `surface` · 덮어쓴 키)를 찍고 결정 행/스트림에도 도장을 남긴다.
   **안 그러면 다음 세션이 오라클 런을 모델 런으로 착각한다.**
3. **폴백하지 않는다**. 읽기 실패면 `error(...)` 로 런을 죽인다 — 조용한 폴백은
   "모델이 아무것도 안 냈다" 와 바이트 구별이 안 된다.
4. **어떤 게이트도 안 낮춘다**. 픽스처가 `check_impl_conventions` 를 그대로 통과한다.

### 7.1 결과 [측정]

| | 대조 | **O1** release 단독 | **O2** cargo ban 단독 | **O3** 둘의 조합 |
|---|---|---|---|---|
| 완주 | COMPLETE | 🔴 **INCOMPLETE** | COMPLETE | *(진행 중)* |
| `t` / `n_closed` | 1024 / 287 | 7599 / 230 | 1024 / 287 | |
| `min_soc` | 0.14903023 | 0.14738419 | 0.14903023 (동일) | |
| `energy_J[R1]` | 8029.6537 | 21658.9352 | 8029.6537 (동일) | |
| **N** | — | **−2.1307** | **0.0** | |
| `n_candidate_edges` | — | 19 | **0** | |
| L4 `world_delta_body` | — | `n_edges=−2, n_binding_changed=8` | 전 축 0 | |

**O1 — release 단독**: 🔴 **사상 처음 L4 ≠ 0.** 기전은 작동했다 — MILP 가 일을 되돌려주지
않았고(`t=251` 실측: R1 **−4.70 J**, R10 **+12.19 J**) 5개 binding 이 다른 로봇에 남았다.
그런데 **받은 쪽이 아낀 쪽의 2.6배를 냈고**, 그 뒤 로봇 6대가 `CARRY`/`TransportUnitGo` 에
얼어붙어 전원이 정확히 2.5 J/step(유휴 바닥)만 태웠다. **경성 교착.** R1 의 21.7 kJ 중
~13.6 kJ 가 교착된 세계에서의 방전이다.

**O2 — ban 단독**: 교착은 안 하는데 **아무것도 안 한다.** 21프레임 **비트 동일**, `N = 0.0` 정확히.
원인은 `n_candidate_edges=0` — 재풀이가 만든 MILP 에 배정 결정변수가 아예 없어
금지가 **0행으로 컴파일**됐다. 🔴 `:banned` 를 성공으로 읽지 않고 독립 확인했다(부담 계층 부재
`@warn` 0건, `ran_milp=true`, 프레임 단위 diff).

**⟹ 후보 간선을 만드는 유일한 것이 O2 가 피하려던 바로 그 release 다.**
"미래를 제약한다" 와 "현재를 푼다" 는 **대안이 아니라 짝**이다. → O3.

### 7.2 🔴 귀속 대조 — 하네스는 무죄다

`OracleNoRelease!`: 같은 레인 · 같은 `surface` · 같은 등록 · 같은 규약 검사 · 같은 바인딩 ·
같은 `invokelatest` · 같은 `reset_cache_resume!` · 같은 MILP 재풀이 — **간선만 0개 푼다.**
결과: `PROJECT COMPLETE`, 스트림이 대조와 **21프레임 전부 모든 물리 축에서 비트 동일.**

⟹ 등록 · 집행 봉투 · `handled=true` 가 기본 복구 사슬을 건너뛰는 것 · 캐시 재개 · MILP 재풀이
**전부 무죄.** 교착의 원인은 **풀린 간선 2개와 그로부터 MILP 가 만든 재배정** 하나뿐이다.

### 7.3 이 계열이 이미 확정한 것

🔴 **병목은 LLM 이 아니다.** 오라클이 이미 이상적인 도구를 썼다. 유료 런 다섯이 식별자 환각으로
죽으면서 이 사실을 가리고 있었다. 남은 질문은 *"모델이 잘하는가"* 가 아니라
**"이 세계에서 mild battery 를 완화하는 개입이 존재하는가"** 다.

⚠️ **사건 설계 자체의 문제도 드러났다**: 대상이 **미래 간선을 2개밖에** 안 갖고 있다.
덜어 줄 것이 그것뿐인데 덜어내는 대가가 수송 팀 해체라면 **구조적으로 순손실**이다.

## 8. 데모가 말할 수 있는 것 / 없는 것

**✅ 말할 수 있다** [측정]
- 학습 분포 **밖**의 사건에서 multi-agent LLM 이 새 Julia 도구를 **썼고**, 규약 검사를 통과해
  **살아 있는 모듈에 등록됐고**, 인자를 받아 **집행됐고**, **광고된 세계 함수를 실제로 호출했다**.
- 사건이 **측정 가능한 물리적 대가**를 갖는다(완주 +140 스텝).
- 지표의 **잡음 바닥이 0** 이다.
- 주조 body 가 **세계를 바꿀 수 있다**(오라클 O1, L4 ≠ 0).

**❌ 말할 수 없다**
- "도구가 build 를 구했다" — mild 는 **구조적으로** build 를 못 깨뜨린다(§9).
- "LLM 이 만든 도구가 세계를 바꿨다" — 유료 런 다섯 다 L4 = 0. 오라클만 0 을 벗어났다.
- "재배정이 에너지를 아꼈다" — O1 은 **−2.13**, O2 는 **0.0**.

## 9. 🔴 사건 설계의 구조적 한계

- `mild` 의 정의 = `soc > REPLACE_SOC_THRESHOLD = 0.1`; 물리적 정지 문턱 = `STALL_SOC_DEFAULT = 0.05`
  ⟹ **mild 로봇은 절대 멈추지 않는다.** 고장이 안 나므로 고칠 것도 없다.
- ⟹ *"incomplete → complete"* 는 mild 에서 **어떤 도구로도 도달 불가**다.
- 원래 목표는 **`zone`** 으로 살아 있다 [측정]: `DEMO_ZONE=1`(🔴 `DEMO_OOD=zone` 은 `case_kinds`
  에서 **하드에러**). zone 스트림 넷이 전부 `n_closed=270/305` 에서 얼고 세 로그가 INCOMPLETE 로
  끝나며 `[router] 'unknown:zone' → escalate to LLM` + `kind_valid(:zone)==[]`(**빈 메뉴**).
  ⟹ **받아낼 팔이 하나도 없는 유일한 kind 다.** mild 에서 만든 배선(광고된 동사 · 사건 대상 채널 ·
  에너지 계측 · 인자 거름 · 오라클 우회)은 **전부 zone 에서 그대로 쓰인다.**

## 10. 열려 있는 결정

1. **O3 이 실패하면**: 광고된 어휘의 **어떤 조합으로도** mild 를 구제 못 한다는 뜻이다.
   그러면 고칠 대상은 LLM 도 어휘도 아니고 **사건 설계**다 → `zone` 으로 간다.
2. **O3 이 성공하면**: 목표 body 가 확정된다. 그 다음 질문은 *"multi-agent 가 그 조합을
   스스로 발견하는가"* 이고, 그것이 이 실험의 원래 명제다.
3. **`_battery_load_features` 의 7.5% 오류** — 모델이 payload 를 추론하는 입력이 틀려 있다.
4. **"옳게 했는가" 칸** — 사다리에 없다. `fault_robot_and_reassign!` 로도 L4 는 초록이 된다.
5. **교착의 원인** — `reset_slot_to_invalid!` 로 비운 슬롯의 낡은 id 전파가 가설이나 `[미측정]`.
