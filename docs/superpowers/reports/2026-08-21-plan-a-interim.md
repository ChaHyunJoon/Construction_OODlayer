## 1. 배경 — 왜 상태를 줄이는가

로봇 여러 대가 레고 모델을 조립한다. 고장·방전·통행금지구역 같은 **계획 밖 사건(OOD)** 이
터지면 무엇을 할지 골라야 한다. 그 선택 문제를 SMDP 로 적고, MCTS 가 **생성 시뮬레이터**
`G(s,a) → (s′, R, τ)` 를 샘플링해 푼다.

`s` 의 역할이 "모델을 재출발시키는 것"에서 **"트리 노드를 색인하는 것"** 으로 바뀌었으므로
**손실 압축이 허용된다.** 판정 기준(spec §2-1):

> 이미 하드코딩된 하위 정책의 관할이거나, `s` 안의 다른 값에서 다시 만들 수 있거나,
> 상수면 상태가 아니다.

그 결과가 `s = (G, Geo, Fleet, Prog)` **7필드**, 로봇당 `(soc, usage_s)` 둘이다.

리뷰어가 덧붙인 두 가지, 둘 다 T14 를 구속한다:

🔴 **Important 1 — `R` 의 에너지 항이 `_hz_excluded()` population 불일치를 물려받는다. 확정.**
`energy_between` 은 `keys(s.fleet)` 만 합산하는데, `s.fleet` 은 **고장 로봇**을 뺀다. 엔진 원장은

## 3. 🔴 계획서·spec 이 틀렸던 지점 (전부 실측)

이 절이 이번 세션의 실질적 성과다. **계획서를 곧이곧대로 따랐다면 에러 없이 조용히 샜을** 것들이다.

### 3-1. 논리 오류 — `Disjunction` 이 ∧ 로 구현돼 있었다

계획서의 `Disjunction` `:eq` 컴파일이 `@constraint(model, l == rhs)` 였다. **논리합을 논리곱으로**
구현한 것이다. Big-M 두 줄로 재구현했다. 오타가 아니라 설계 논리 오류다.

### 3-2. spec §2-6 결함 — `mode_of` 가 λ 를 20배 틀리게 한다

spec 은 `mode` 를 `s.g.binding` 에서 유도한다고 적었다. `_responsible_robots` 는 **팀 전체**를
돌려주는데 `simstate_of` 는 `binding` 에 **한 명만** 남긴다. 그래서 나머지 팀원이 `:carry` 대신
`:idle` 로 분류되고, `mult_carry = 2.0` vs `mult_idle = 0.10` → **λ 가 정확히 20배 틀린다.**
계획서 판 `mode_of` 를 넣으면 시험 24개가 실패한다(실측).

**정정된 정의:** *어느 노드가 활성인가* 는 `s` 에서, *누가 맡는가* 는 `env.sched` 에서.
spec 에 정정 커밋 완료(`b0fc40f8`).

### 3-3. spec §4-1 결함 — D-6 는 "상한"이 아니고, 안전 방향이 반대다

계획서는 새 rate boundary 를 **"상한 근사"** 라고 적고 크기 판정을 N-G1 에 미뤘다. T8 이 **모드
상수 구간** 21개에서 재측정: over/exact/under = **4 / 11 / 6**, 평균비 **0.939** — 상한이 아니라
**순 과소추정**이다.

그리고 안전 방향이 서술과 반대다. `sample_sojourn` 은 `min(T_plan_next, …)` 까지 적분하므로
**과대추정이 위험한 방향**(실제 경계를 넘어 낡은 λ 를 씀)이고 과소추정은 보수적이다.

⚠️ 그리고 그 표의 **중앙값 1.000 은 측정값이 아니라 `dt_sim = 0.025 s` 눈금**이다 — "정확히
1.0"인 11개가 곧 ≤3스텝 구간 11개이고 **두 집합이 일치한다.** 분해 가능한 10개만 보면 중앙값
**0.634**.

### 3-4. 게이트가 자기 효과를 분해하지 못했다

계획서가 N-G1 에 지정한 `n = 200` 은 **c ≈ 1.56 까지만 분해**한다. 그런데 물리가 만들 수 있는
`c*` 는 **1.067** 이다. **즉 계획서의 게이트는 검출하려는 효과를 검출할 수 없었다.**

T9 이 그 자기 분해능 검사를 **분포를 보기 전에** 하드 단언으로 넣었고, 허용오차를 **측정이 아니라
유도**했다 — KS 임계 상수 + 지수 항등식 + 실행 시점에 읽은 값. 리터럴 없음, 디렉토리 간 잔차 없음.

**그리고 N-G1 은 FAIL 했다:** KS **0.1189**, p **2.24e-58**. 즉 경량 레인의 sojourn 분포가 엔진과
유의미하게 다르다. 진단은 §7-3 에서.

### 3-5. 안전 논증이 무너지는 자리 — 예외는 전이가 아니다

C2 가 `(t0, tF, Xa)` 를 LLM 에 열자, **파싱에 성공한 제약이 시뮬레이션을 죽이는** 경로가 생겼다.
`_var_of` 가 `error()` 를 던지고 그게 `verify()` → `maybe_respecify!`(try 없음) →
`route_planning.jl` 로 맨몸으로 올라온다. 이 태스크의 안전 논증은 "`verify()` 가 전이함수의 문이고
거부는 NOOP 과 같은 전이"인데, **예외는 전이가 아니라 전이의 부재**다. 게다가 새 프롬프트가 그
입력을 유도하고 있었고, 시험이 `@test_throws Exception` 으로 **크래시를 정답으로 못박고** 있었다.

→ `Reject` 로 바꿨다. **"조용한 폴백 금지"는 성공을 가장하는 것을 금지하지 실패를 분류하는 것을
금지하지 않는다.**

## 4. 🔴🔴 근본 원인 규명 — 왜 아무것도 재현되지 않았는가

전문: `.superpowers/sdd/2026-08-21-reduced-state-smdp-action-synthesis/nondeterminism-investigation.md`

### 원인

**Julia 는 `ConstructionBots` 를 재precompile 할 때마다 새 모듈 `build_id` 를 발급한다.** 그것이
`TypeName.hash` 를 시드하므로 **CB 가 정의한 모든 ID 타입의 `hash`/`objectid` 가 바뀐다** → 그 ID 를
키로 쓰는 `Dict`/`Set` 의 순회 순서가 바뀐다 → `hierarchical_geom_essentials.jl:872` 의
`recurse_child_geometry` 에서 그 순서가 **답에 도달한다** → 그 점 순서가 **bounding-sphere 적합**에
들어간다 → 물체 격자 배치가 순열 → **배정 DAG 가 갈린다.**

### 증거 (코드 차이 0)

`touch src/ConstructionBots.jl` — 바이트 하나 안 바꾸고 재precompile 만 강제:

| | `hash(ObjectID(1))` | pre-sim makespan |
|---|---|---|
| 전 | `16361513805601183855` | 35.225 |
| 후 | `8753457096344937538` | **34.950** (배정 DAG 도 다름) |
| 다시 (touch 없이) | 후와 동일 | 후와 동일 |

**단계 이분법이 결정적이다:** 파싱·모델 스펙·씬트리 id 순서·`HyperrectangleKey` 는 **비트 동일**한데
**`HypersphereKey` 가 첫 상이 지점**이다. 사각형은 min/max 라 순서 불변, **구 적합은 순서 민감** —
그게 서명이다.

**한 디렉토리 3회 반복은 바이트 동일** — 프로세스 수준 비결정성은 **존재하지 않는다.**

### 이것이 뒤집는 것

- 🔴 **`.claude/CLAUDE.md:223` 의 "살아 있는 결함 #1" 은 줄번호도 진단도 낡았다.** 지목된
  `_pick_active_robot` 은 이미 정렬한다(`_ordered_active`, `:912`). 이미 옳은 서술은 `:311-314`
  ("결정성의 단위는 디렉토리")이고, 이제 거기에 **기전과 4분짜리 재현기**가 붙었다.
- 🔴 **`state_hash` 는 디렉토리/재컴파일을 건너 이식 가능한 키가 아니다.** `prog.closed` 가 **정점
  번호**를 저장하므로 **두 세계에서 같은 해시가 나오면서 실제 닫힌 작업은 다를 수 있다**(실측).
  방향이 반대인 두 실패가 동시에 난다 — 다른 세계가 병합되고, 같은 세계가 병합되지 않는다.
  → **트리는 행동 경로로 색인하고, `state_hash` 는 한 디렉토리 안의 진단으로만 쓴다.**
- 🔴 **"전/후" 측정 중 재컴파일이 끼어 있으면 코드 변화 ⊕ 세계 변화를 잰 것이다.**
- 🔴 **MCTS 는 포크할 때가 아니라 포크를 *전환*할 때마다 `rvo_rebuild!` 해야 한다** (T12 실측).
  RVO2 가 프로세스 전역 하나라 **마지막으로 재구축된 env 를 따라간다.** 갈래 비용이 갈래당이
  아니라 **노드 방문당**이라는 뜻이다.

## 7. 🔴 사용자 판단이 필요한 것

### 7-1. D-4 가 known 세계에 zone 기전을 켠다 (실험 타당성)

### 7-4. `engage_fallback!` 의 문서가 거짓이고, 재발이다

즉 실제 의미론은 **"첫 fallback = 런의 영구 종료"** 이고 문서는 반대를 말한다. 그리고 이건
**재발**이다 — `verifier.jl:258` 에 똑같은 실패 모양이 **2026-08-18 에 정정된 기록**이 있다

다시 나왔다.**

셋 중 하나가 필요하다: 실제로 부르거나 · docstring 을 "terminal" 로 고치거나 · 정지가 스스로
만료되게 하거나.

### 7-5. 기하적 불가능이 **fail-stalled** 다
