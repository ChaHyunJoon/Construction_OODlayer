## 3. 🔴 이 작업이 무엇의 증거가 **아닌가**

이 절이 이 보고서의 본론이다. 아래 어느 항목도 나중에 조용히 좁히면 안 된다.

### 3-1. 🔴 네 번의 유료 관측 전부에서 `tools_offered = 1` 이었다 — 모델은 개입 수단을 손에 쥔 적이 없다

줄리아가 **두 레인 모두** `valid=["NOOP"]` 를 보냈다 **[실측-인계]**. 즉 모델에게 실제로
제시된 tool 은 `no_intervention` **하나뿐**이다. 두 원인을 각각 코드에서 확인했다
**[실측-본인]**:

- **zone**: `tools/monitor/policy.jl :: valid_macros` 의 `ZoneTruth` 분기는
  `NOOP ∪ ActionRegistry.kind_valid(:zone)` 를 돌려준다. 그런데 `v4-3arms` 어휘의 세 매크로
  (`NOOP`/`Replace`/`SwapBattery`)의 `kinds` 는 `["fault","battery"]`·`["fault","battery"]`·
  `["battery"]` 뿐이라 **`zone` 을 kind 로 가진 팔이 하나도 없다** ⟹ `kind_valid(:zone) == []`.
- **mild**: `wm4spacecraft_manufacturing/oracle/action_registry.jl :: battery_arms` 의 mild
  분기가 `return [i for i in up if COST[i] == 0.0]` 다 ⟹ 비용 0 인 `NOOP` 만 남는다.

**둘 다 우연이 아니라 설계다.** 그러므로:

1. `expressible == True` 는 "메뉴가 하나인 상황에서 그 하나로 족하다" 는 뜻이고, 개입 팔과
   비교한 판단이 **아니다**. 뒤집힐 여지가 구조적으로 좁았다.
2. 모델의 문장 *"NOOP is clearly better than any other action"* 에서 그 "other action" 은
   **tool 로 제시된 적이 없다.** 이 문장을 대안 비교의 증거로 읽으면 안 된다.
3. ⟹ **S1 의 전제(모델이 받는 값을 옳게 만든다)는 필요조건이었지만 충분조건이 아니었다.**
   **다음에 판정해야 할 것은 서술자가 아니라 메뉴/어휘 정책이다** — `valid` 를 짓는 자리,
   즉 `battery_arms` 의 mild 분기와 `kind_valid(:zone)` 의 공백.

### 3-2. 🔴 "유료 4건" 중 둘은 DSPy 디스크 캐시 재생이었다 — 음성대조는 오늘의 모델을 재지 않았다

### 3-3. 🔴 S1 이 산 것은 **논증의 사실성**이지 결정의 변화가 아니다

| 서술자 | 모델이 댄 이유 |

| 옛 (`harm 0.00`) | *"The harm, work at risk, and resource loss are all **measured at 0.00**, indicating no immediate threat to the assembly process."* |

옛 문장은 **판 위에서 거짓이다** — 같은 프롬프트가 `work frozen by those = 32`,
`(the build has 251 unfinished nodes in total)` 를 3169자 떨어진 곳에 함께 싣고 있었다

⚠️ **그러나 서술자가 모델을 움직였다고 주장하면 안 된다.** 모델은 `harm = 1.00` 을 **한 번도
인용하지 않았다** — 문자열에 "harm" 도 "1.00" 도 없고, 원자료 비율(3/131, 0.13)로 논증했다
**[실측-인계]**. 서술자가 프롬프트에 닿는 것과 그것이 판단을 지배하는 것은 별개다.

⚠️ 그리고 **팔마다 n=1 이며, 캐시가 재표집을 구조적으로 막는다**(동일 프롬프트는 영원히
동일 바이트를 돌려준다). 그러므로 이 문장 변화는 **표집 잡음과 분리할 수 없다.**

### 3-5. `expressible == False` 비율은 부분적으로 **프롬프트 준수**를 잰다

*언제* false 라고 말할지를 가르친다. **이 레인의 어떤 초록도 "모델이 추론했다/안 했다" 의
증거로 인용하면 안 된다.**

### 3-6. 프로브 격리는 **zone 에만** 됐다

zone 은 필요한 값이 전부 저장된 스트림에 있어 요청 본문을 재구성할 수 있었다. **battery 는
원리적으로 격리가 안 된다** — payload 값은 결정 시점에 **새로 재는** 값이라 스트림에 없다.
게다가 어느 스트림도 `/macro` **요청 본문**을 영속하지 않는다(`respec.input` 의 키에 `payload`
가 없다) **[실측-인계]**. ⟹ **mild 의 결과를 zone 과 같은 종류의 증거로 인용하면 안 된다.**

### 3-7. 임계 변경이 **물리를 같이 바꿨다**

spec §2 의 (a)(프로브)와 (b)(보드)는 **다른 것을 잰다**. §5 의 임계 사다리 변경은 보드가 도는
세계 자체를 바꾸므로, 두 관측을 한 숫자로 요약하면 안 된다.

### 3-8. 임계 열거의 **방법은 네 번 실패한 뒤에 성공했다**

계획은 상수 **6개**를 지목했다. 실제 자리는 **16개**였다. 네 번 연속의 리뷰가 **매번**
직전 스윕이 "완료" 라고 선언한 자리를 하나씩 더 찾아냈고, 그중 하나
(`wm4spacecraft_manufacturing/sweep/llm_ood_eval.py` 의 `--bsoc` 기본값)는 **이 레인이 스스로
만든 회귀**였다 **[실측-인계]** (지금은 0.96 **[실측-본인]**).

🔴 **그러므로 사다리 전역 정합성은 확립된 것으로 적을 수 없다.** 주장할 수 있는 최대치는
**"지금까지 누구든 들여다본 모든 곳에서 정합적이다 — 다만 그 탐색의 구성이 완전성을 보장하지
않는다"** 이다. 보증은 여전히 **어휘적(lexical)** 이다.

### 3-9. SoC 경계를 지키는 게이트에는 **열거된 사각지대가 남아 있다**

`test/soc_ladder_is_coherent.jl` 의 (6c) 근접성 스캔은 자기 머리말에 다섯을 **직접 적어 둔다**
**[실측-본인]**: (1) 기호에서 40자 초과 거리, (2) 딕셔너리/설정 간접참조, (3) 문자열 리터럴
안의 `#` 이 주석 스트리퍼를 오작동시켜 **진짜 컴파일되는 코드를 지운다**, (4) `#`-주석 안의
`"""` 가 뒤의 진짜 docstring 과 오짝지어진다, (5) (6)/(6b) 카탈로그에 없는 다섯 철자의 일부.

⟹ **경계가 기계로 보장된다고 적으면 안 된다.** 게이트가 실제로 막는 것은 "특정 철자의 폴백이

## 7. spec §7 이 **단위 게이트로 못 만든 두 행** — 보드 한 판이 증거이고, 그것은 n=1 이다

spec §7 의 게이트 표 중 둘은 **진짜 `env`** 를 요구해서 단위 게이트가 되지 못했다. 좁히지 않고
그대로 인용한다.

| spec §7 항목 | 왜 미뤘나 | 무엇이 대신 확인했나 | 결과 |
|---|---|---|---|
| *"`heaviest_payload_kg` 가 실제 화물에서 나온다 — `_payload_mass` 를 상수 0 으로 변이시키면 빨개진다"* | `_payload_mass` 는 `env.scene_tree` 에서 화물 형상을 읽는다. 최소 fixture 로는 못 만든다 | T5 의 mild 보드가 `llm_input` 에 실린 값을 본다 | **통과** |
| *"프로브 전후 env 지문(`nv`·`ne`·`closed`) 동일"* | 같은 이유 — 진짜 `OperatingSchedule` 이 필요하다 | T5 의 보드가 `[milp-probe]` 를 찍고 정상 진행하는 것 | **통과(단, zone 판은 완주 못 했다 — §3-10)** |

**첫 행의 실측** **[실측-인계]**: `heaviest_payload_kg = 2.29376`, **5/5 프레임에서 0이 아니고**,
`_payload_mass failed` `@warn` 은 0건. 독립 검증자가 값을 **재유도**했다 —
`payload_density=100.0` 에서 `prod(r) = 0.0028672`, 보드의 `scale=0.008` 로 나누면
`prod(r/scale) = 5600.0` **정확히 정수**(LDU³, 예: 반치수 10×20×28 LDU = 1×2 스터드 부피).
⟹ 값은 실제 화물 기하에서 나왔다.

🔴 **두 명제 모두 "게이트가 지킨다" 가 아니라 "보드 한 판이 증거다" 이고, 그것은 n=1 이다.**
특히 첫 행은 `tools/monitor/policy.jl :: _battery_load_features` 의 `RobotGo`-대신-successor
조용한-0.0 버그에 대한 **레포 전체를 통틀어 유일한 검사**다. `test/battery_load_features.jl` 이
자기 머리말에 그렇게 적어 두었고, 그것이 옳은 처리다.
